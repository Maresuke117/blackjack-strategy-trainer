📜 ブラックジャック アプリ コーディング規約
1. 命名規則（名前の付け方）
名前を見ただけで「それが何であるか」がわかるようにします。

ファイル名: snake_case（スネークケース）を使用する。

例: game_screen.dart, playing_card_model.dart

クラス名: UpperCamelCase（アッパーキャメルケース）を使用する。

例: GameEngine, HandWidget

変数・関数名: lowerCamelCase（ローワーキャメルケース）を使用する。

例: currentBalance, calculateTotalScore()

定数: lowerCamelCase を基本とする（Dartの標準推奨）。

例: const defaultBetAmount = 10;

2. コメント規則（必須ルール）
「なぜこの処理をしているのか」を未来の自分や仲間に伝えるために、以下のルールを適用します。

クラスの冒頭: そのクラスの「役割」を必ず記述する。

公開メソッド（関数）: その関数が「何を受け取り」「何を返すか」「何をするか」を必ず記述する。

ドキュメントコメント: Dart推奨の ///（スラッシュ3つ）を使用する。

例:

Dart
/// プレイヤーの手札を管理するクラス。
/// 合計値の計算やバスト判定の責任を持つ。
class Hand {
  /// 手札に新しいカードを追加する。
  /// [card] 追加するトランプのオブジェクト。
  void addCard(PlayingCard card) { ... }
}
複雑なロジック: コード内の一部で複雑な計算（フィボナッチ法の移動など）を行う場合は、その行の横や上に // で補足説明を入れる。

3. 設計・構造ルール（疎結合・保守性）
設計書で決めた「疎結合」と「コンポーネント化」を維持するためのルールです。

ロジックとUIの分離:

Widget（UI）の中に計算ロジック（勝敗判定やベット額計算など）を直接書かない。

計算は必ず logic/ フォルダ内のクラス（GameEngineなど）で行う。

コンポーネントの再利用:

2回以上同じような見た目が登場する場合は、必ず widgets/ フォルダに切り出して共通化する。

Riverpodの使用:

データの受け渡しにはグローバル変数を使わず、必ず Provider を介して行う。

4. ファイル構成（フォルダ分け）
整理整頓を徹底します。

lib/models/: データ構造（Card, Handなど）

lib/logic/: 計算・ルール（GameEngine, BettingSystemなど）

lib/screens/: 各画面の全体レイアウト

lib/widgets/: 再利用可能な部品（CardWidgetなど）

lib/providers/: 状態管理（Riverpodの設定）

5. 書式（フォーマット）
自動整形: コードを書いた後は、必ず dart format（Flutter標準の整形コマンド）を実行して、インデント（字下げ）などを整える。

1ファイルの長さ: 1つのファイルが長くなりすぎないようにする（目安として500行を超える場合は分割を検討する）。
